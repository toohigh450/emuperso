2. Bugs réels trouvés et corrigés grâce aux tests terrain

Bug 1 — PS1 : la carte mémoire « disparaissait » au relancement

Symptôme (Karl) : sauvegarde en jeu OK avec le BIOS personnel, mais au relancement sans fermer le navigateur, « no savegame found ».

Diagnostic (sondes navigateur) : le moteur recharge bien le .srm en RAM au boot (marqueur prouvé session 1 → session 2) ; le maillon faible était la course au déchargement : autoSaveBattery au pagehide/beforeunload est asynchrone (IndexedDB) et peut être tué avant la fin.

Correctifs :

  • RC-1.19 : miroir synchrone localStorage de la carte + écoute freeze + newestBattery() au lancement
  • RC-1.20 : le miroir était écrit après await vault.put — trop tard si la page mourait pendant la transaction. Désormais le synchrone part avant.

Preuve mécanisme (browser_unload_probe.py) : marqueur 128 Kio → pagehide → IndexedDB supprimée entièrement → reload → session 2 → marker_in_session2_ram_despite_empty_idb: true. La carte revient en RAM grâce au seul miroir localStorage. Ce que ça ne prouve pas : la capture d'une vraie sauvegarde en jeu au bon moment ni sa relecture par le jeu après fermeture complète — le test d'acceptation reste : sauvegarder dans Future Cop → fermer l'onglet → rouvrir → charger la sauvegarde en jeu.

Bug 2 — GameCube : même race sur la carte mémoire 2 Mio

Le cardDB.set IndexedDB au pagehide avait le même risque. Correctif : miroir localStorage synchrone avant l'écriture async, loadCard prend le plus récent par timestamp.

Preuve (test-card-persist.py) : import .mcr marqueur → cardDB.set en échec + IndexedDB tuée → reload → « 2 Mio enregistrée » restaurée depuis le seul miroir (card_recovered_despite_empty_idb: true).

Bug 3 — GameCube : bouton « Choisir une image » mort

Le sélecteur de fichier n'était pas câblé (#pick sans handler). Corrigé (commit 3c2b656), redéployé.

Bug 4 — PS1 : BIOS personnel jamais écrit (cross-realm)

Le File du realm parent échouait au test instanceof Blob dans l'iframe → le BIOS n'atteignait jamais MEMFS. Corrigé par réencapsulation dans le realm du moteur. Vérifié : le cœur log found BIOS file + BIOS: 19951204, 'CEX-3000/1001/1002 by K.S.'.

3. Isolation des sauvegardes par contenu

Portables (NES→PSP, N64, PS1) : identité par empreinte SHA-256 du contenu. Deux versions réelles de Chrono Trigger ([!] vs [h1C]) → deux empreintes → deux saveSpaceId distincts. La preuve porte sur la séparation des identités logiques ; une écriture/relecture croisée n'a pas été exécutée — la formulation « jamais » serait trop absolue sans cet essai.

snes:snes9x:06d1c2b06b716052…  (version vérifiée)
snes:snes9x:3f82b0b7ce181613…  (version hack)

GameCube : la carte était initialement clé par le nom de fichier (point GPT-02 — deux images homonymes ou renommées partageaient la carte). Corrigé : les images disque portent un ID unique dans leur en-tête (6 caractères à 0x00, déjà lu par gameCubeIdFromHead) → clé gc:ID. Repli non destructif sur l'ancienne clé stem pour les cartes existantes (lecture seule, aucune migration destructive). Formats sans ID (.rvz, .dol, .zip) conservent la clé stem.
