La copie candidate provient de ce ZIP, pas d’une reconstruction supposée d’une version antérieure. Preuve de réception.

Avant correction, Codex a rejoué sur la référence : 59 tests JavaScript, 8 Python, 21 contrôles Chromium et 4 contrôles DOM, tous réussis. 2. Q1 — recalcul cryptographique complet

RÉUSSI pour ces deux fichiers précis. Le vérificateur tools/verify_exports.mjs est indépendant du code produit : il n’importe ni common.mjs, ni Journal, ni Storage. Il utilise node:crypto, pas le WebCrypto de l’application. Il lit les JSON sans les réécrire et ne restaure aucun état. La revue interne indépendante utilise une autre implémentation Node et une contre-vérification Python sur ce corpus.

La sérialisation de la 1.0.1 est récursive : clés d’objets triées par Object.keys(x).sort() (ordre UTF-16), tableaux dans leur ordre, nombres finis et chaînes par JSON.stringify. Pas d’espaces ajoutés ni saut de ligne final dans la préimage, puis encodage UTF-8 sans BOM et SHA-256. La préimage d’événement est {previous_sha256, event} canonisée ; le champ sha256 lui-même n’en fait pas partie. Le payload est canonisé seul ; l’enveloppe exclut uniquement son champ envelope_sha256 et inclut le payload. Le formatage indenté du fichier brut est distinct.

3. Q2 — refus d’identité et traçabilité des injections

Dans le journal terrain, les séquences 8, 15 et 22 sont des échecs load / E_IDENTITY, aux générations 2, 4 et 6. Aucune identité chargée ou lancée n’est confirmée pour ces tentatives. Une sélection PAL-A suivie d’un chargement/lancement synthétiques réussis intervient ensuite. Les trois refus ont été reproduits en simulation avec dishonestLoadedHash: true, qui renvoie 64 zéros au lieu du SHA de la fixture. Le contrôleur refuse l’acquittement avant de passer à LOADED, invalide l’instance et n’autorise aucun lancement.

La cause historique exacte n’est pas prouvée par ces JSON seuls. Ils ne consignent pas le mode d’injection actif. La description du code et les captures évoquées dans les audits rendent l’injection plausible ; elles ne constituent pas une trace interne absente. La correction ne contourne pas E_IDENTITY : le garde-fou était justifié.

La candidate ajoute simulation.configuration à chaque initialisation, lié à la génération : délais, méthodes en échec et flags d’identité. Elle affiche la configuration retenue et consigne les paramètres normalisés des steps et les demandes audio. command.failed.details fournit les SHA attendu/reçu pour le refus de chargement ou la méthode en échec injecté. Changer le menu seul ne change pas l’instance active ; la nouvelle sélection vaut au prochain init.

Ces informations sont des relevés de configuration du simulateur, pas une attestation hostile. Une injection mutée pendant un test n’est pas rétroactivement ajoutée à la configuration d’initialisation ; son échec indique injected et method. Les nouvelles séquences/hashes diffèrent légitimement avec les événements ajoutés ; aucun ancien journal n’est réécrit.

4. Q3 — horloges, frontières et récupération PCM

Le seuil réel du code est strictement hors [0.95, 1.05]. La vitesse est window_emulated_ms / window_wall_ms, cumulée depuis start/resume/rebuildHost. Il ne s’agit ni du dernier delta seul, ni des compteurs absolus depuis l’ouverture du Lab. Une reprise réancre la fenêtre et remet speed à null jusqu’au prochain avancement.

Les sondes contenues dans guard.paused sont capturées avant l’appel de pause : simulated_loops=1 dans cet événement n’implique pas une boucle encore active après le garde-fou. L’état du contrôleur et sa sonde après pause confirment la boucle à zéro.

Les frontières 0,949/0,950/0,951 et 1,049/1,050/1,051 sont testées en isolant la consommation PCM. Les bornes sont acceptées ; les valeurs hors borne entraînent la pause. Les fenêtres nulles/négatives/fractionnaires, NaN, Infinity, chaînes et valeurs au-delà de 10 000 ms sont refusées.

Défaut confirmé et corrigé : la 1.0.1 comparait le compteur cumulatif d’underruns à zéro. Après une pénurie puis une reprise, un step normal entraînait encore PAUSED à cause d’un événement passé. La candidate conserve ce cumul pour les diagnostics mais ne déclenche la garde que sur une nouvelle hausse pendant le step courant. Le scénario coupure → reprise normale → nouvelle coupure est passé en Node et dans l’UI. Un FULL fictif continue de pouvoir coexister avec vitesse normale.

Validation corrigée : les options PCM mal typées étaient converties implicitement, et une mauvaise fenêtre validée après contact avec l’adaptateur détruisait l’instance. La candidate valide les options connues, entiers et booléens avant tout appel mutateur ; les erreurs d’entrée conservent l’instance et la génération. L’adaptateur valide aussi ses appels directs. Ces choix changent explicitement le traitement des entrées invalides, avec tests de non-régression ; aucune performance N64 n’est mesurée.

8. Windows et limites de preuve

Les deux fichiers sont des exports terrain fournis par Karl, avec user-agent déclarant Windows 10 / Chrome 156, cross_origin_isolated=false et des tests de présence de constructeurs. Codex n’a pas opéré ce PC. L’origine de page n’est pas exportée : l’ouverture file:// décrite par un audit n’est pas indépendamment démontrée par ces JSON. Le recalcul des hashes ne rend pas ces champs authentifiés.

Ce parcours rapporte sélection, refus d’identité, lancement synthétique, deux pauses et un snapshot ; il ne prouve ni restauration, rechargement, navigation clavier, Edge/Firefox ou validation Windows complète. La candidate n’a pas été exécutée nativement sous Windows ici. Ces points sont NON TESTABLES ici, pas réussis par déduction. Le formulaire Windows fournit une matrice Chrome/Edge/Firefox, modes séparés, sans résultat prérempli.

Un succès Chromium/Linux ou Node n’atteste pas ces environnements. Un timeout/AbortSignal invalide logiquement la session sans démontrer l’arrêt physique d’un moteur non coopératif. Le simulateur n’est pas une sandbox de JavaScript hostile. Les sources/licences candidates moteur, le SDK et la fermeture de dépendances n’ont pas progressé dans cette révision ; leurs inconnues restent ouvertes.
