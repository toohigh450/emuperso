N64 Web Lab — Phase 1A, révision 1.0.1

Réponse aux audits GPT/Méo et durcissement du rendu asynchrone du journal. Rapport autonome, sans script ni ressource externe.

GO : laboratoire synthétique sans ROM. La révision est implémentée et testée dans le périmètre Phase 1A. Aucun moteur N64 n’est intégré, compilé ou exécuté ; aucune compatibilité Conker ni correction Sonic n’est démontrée.

1. Ce que disent les audits reçus

GPT et Méo acceptent le socle synthétique 1.0.0, avec réserves. Tous deux déclarent avoir reproduit les 53 contrôles JavaScript, 8 contrôles Python, le manifeste et la reconstruction exacte. Ils n’ont pas reproduit les 21 contrôles navigateur de Codex. Ce sont leurs constats sur la version 1.0.0, pas des validations indépendantes de 1.0.1.

L’identité du ZIP qu’ils ont étudié est 4edef1f9db2bb0a3864fb4dc6951af6afa8b365a343f2114deb3c5b2ea29a8b2. La livraison initiale reste intacte. Les audits reçus sont inclus sans modification dans docs/audits-recus/.

2. Modification précise et preuve limitée

GPT signale une hypothèse de robustesse : plusieurs rendus lancent des exports asynchrones du journal et seul le changement d’instance est filtré. Un résultat ancien pourrait remplacer le résultat plus récent s’il arrivait après. Aucun incident spontané ni corruption de la chaîne n’a été établi. Les promesses du journal sont normalement ordonnées par leur chaîne ; les tests de cette révision provoquent explicitement un ordre inverse pour durcir la couche d’affichage.

src/latest-result.mjs fournit des tickets opaques uniques. Chaque rendu invalide les tickets précédents. Les callbacks de succès et d’erreur dans src/ui.mjs ne peuvent écrire que si leur ticket est encore courant et leur instance reste active. La création d’un laboratoire invalide aussi le ticket. Une erreur courante demeure visible ; une erreur ancienne ne remplace plus le message courant. Si le dernier export échoue, la dernière liste confirmée reste affichée avec le message d’erreur.

Cette barrière ne modifie ni les événements, ni leurs SHA-256, ni la logique du contrôleur, ni les snapshots. Elle ne tue pas physiquement un calcul en cours. Le modèle, les formats et les identités synthétiques sont conservés.

6. Utilisation et reproduction

Extraire le ZIP et ouvrir N64-Web-Lab-Phase1A.html. En cas de WebCrypto bloqué pour file://, utiliser l’alternative localhost décrite dans le guide français. Aucun compte ni dépendance réseau requis à l’usage. Après ouverture : initialiser, sélectionner une fixture, charger, lancer, snapshot, restaurer et vérifier/exporter le journal. Aucun fichier ROM n’est accepté.

Rejouer node tests/core.test.mjs, python -m unittest discover -s tests -p test_tools.py -v, puis les deux scripts navigateur si Playwright et Chromium sont disponibles. Leur chemin Chromium Linux est explicite et doit être adapté sur un autre environnement. python tools/build.py assemble seulement le HTML local ; python tools/verify.py vérifie les fichiers listés sans exécuter leur contenu.

Les preuves courantes sont dans evidence/. evidence-v1.0.0/ et Rapport-Phase1A-v1.0.0.html sont des archives historiques de la version initiale : leurs chiffres, empreintes et références de chemins appartiennent à 1.0.0. Ce rapport-ci décrit la révision courante.

7. Risques ouverts et recommandation

Les douze problèmes ouverts restent applicables : licences complètes, dépendances réellement liées, SDK et archives, compatibilité des révisions à l’exécution, isolation/terminaison hôte future, RAM seulement, terrain Windows et limites des empreintes. Aucune recherche ou compilation moteur supplémentaire n’a été engagée pour cette correction.

STOP moteur réel : aucune compilation/exécution d’un cœur, ROM ou état original, modification Conker/TN-1/Hub, publication ou dépense n’est autorisée par cette livraison. Le GO actuel a été appliqué à la consolidation Phase 1A. Une étape moteur nécessite un GO explicite et borné de Karl.

Suite recommandée immédiate : exécuter le protocole Windows sans ROM et recueillir le diagnostic local. Les blocages documentaires peuvent ensuite être instruits dans un mandat séparé, avant tout essai réel. Ce rapport n’ordonne aucun test TN-1. Décision finale : Karl.
