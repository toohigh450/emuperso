04 — Réponses aux quatre questions de GPT

Q1 — Recalculer les empreintes d'événements, du payload et de l'enveloppe avec la sérialisation exacte du code 1.0.1

Pas encore fait. Méo a vérifié la liaison de la chaîne et l'égalité des empreintes déclarées entre fichiers, pas le recalcul cryptographique complet. Cette question reste ouverte et doit être traitée avant toute affirmation plus forte sur l'intégrité des exports.

Q2 — Pourquoi les trois premiers chargements ont-ils échoué sur E_IDENTITY, et le refus survient-il au bon endroit ?

Répondu, à partir du code 1.0.1. Le refus est à la bonne place : la porte de chargement du contrôleur (src/controller.mjs, fonction load()) exige que l'adaptateur confirme la fixture sélectionnée (result.simulated === true et result.fixture_sha256 === selected.sha256), sinon E_IDENTITY, état ERROR, loaded_sha256: null, aucun lancement. Le mécanisme d'échec est l'injection de défaut « identité » de l'interface : quand le mode identity est armé (src/ui.mjs), l'adaptateur simulé retourne un hash mensonger ('0'×64, src/simulator.mjs, option dishonestLoadedHash). C'est cohérent avec la capture d'écran de Karl montrant le menu « Identité de chargement non concordante », puis avec son changement de menu vers « Échec après restauration, avant reprise » avant le chargement PAL-A réussi. Le test unitaire correspondant (tests/core.test.mjs : « identité mensongère au chargement ne produit aucun lancement confirmé ») décrit exactement ce comportement. Conclusion : le garde-fou a fonctionné, ce n'est pas un bogue du produit. Une limite demeure : le journal lui-même n'enregistre pas le mode d'injection actif au moment des échecs — le lien repose sur le code et les captures, pas sur une preuve interne au journal.

Q3 — Comparer les deux déclenchements E_CLOCK_DRIFT avec la logique exacte de seuil

Pas encore vérifié. Les deux déclenchements (seq 35 : mur virtuel 1 000 ms, émulé 1 800 ms, vitesse 1,8 ; seq 58 : mur virtuel 3 000 ms, émulé 4 600 ms, vitesse 1,8) sont constatés dans les sondes, mais la logique de seuil exacte du code n'a pas été comparée dans ce contre-audit. À ne pas confondre avec des performances réelles : toutes les valeurs sont simulées.

Q4 — Le protocole Windows complet (clavier, rechargement, exports, Edge/Firefox) a-t-il été effectué ?

Réponse : non. Ces deux JSON prouvent un parcours Chrome en file:// sur Windows, avec exports snapshot et diagnostic. Ils ne prouvent ni Edge/Firefox, ni rechargement de page, ni navigation clavier, ni restauration. Le protocole Windows complet reste à faire.
