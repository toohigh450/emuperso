Défaut confirmé et correction

RC-1.14 fermait le jeu en cours avant de vérifier la mémoire d’une nouvelle archive. La reproduction instrumentée montre la session fermée puis le refus mémoire. RC-1.15 contrôle avant toute capture/fermeture, puis après confirmation. Le refus préserve le moteur, sa RAM et ses sauvegardes. Le refus peut être conservateur : aucune hypothèse sur une future collecte mémoire.

Après fermeture explicitement acceptée, un échec reste irrécupérable pour l’ancien moteur. Le dialogue et le message d’erreur le précisent ; seules les sauvegardes déjà enregistrées sont conservées. La décompression reste non bornée : facteur 4,5 indicatif, métrique navigateur non portable, mesure avant/après ne donnant pas le pic.

Tests locaux réellement exécutés

185 tests JavaScript et 10 Python passés. Vrai cœur PCSX sous Chromium Linux avec ISO/ZIP synthétiques : 7 cas régionaux avec contrôle positif RAM ; persistance/restauration après fermeture complète de Chromium ; 13 contrôles de fautes ; 11 contrôles archives et codes composés. Les exceptions sont instrumentées à la frontière JS/native. Le budget mémoire du cas de refus est forcé ; aucune saturation réelle provoquée.

Les captures et JSON sont des preuves locales, distinctes de la CI Node/Python Windows/Linux. Les tests du contrôleur utilisent des doubles pour certains composants ; les harnais navigateur utilisent le vrai cœur. Aucun navigateur Windows ou matériel physique n’est certifié.
